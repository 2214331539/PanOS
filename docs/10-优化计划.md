## 一、背景与定位分析

### 1.1 PanOS 当前状态

V1 已完成：macOS 风格桌面外壳（窗口系统、Dock 鱼眼放大、Spotlight、明暗主题、毛玻璃 vibrancy）、六个内容 App（About / Articles / Projects / Gallery / Links / Contact）、内容管理后台闭环、26 例 E2E 测试、部署配置就绪。

### 1.2 赛道观察

OS 风格个人站是一个成熟的细分赛道（代表作：dustinbrett.com 的 daedalOS、众多 macOS 风格 portfolio）。这类站点的用户心智与传统博客有本质区别：

| | 传统博客 | OS 风格个人站 |
| --- | --- | --- |
| 留存逻辑 | 内容质量单轮驱动 | **探索乐趣 + 内容质量**双轮驱动 |
| 第一印象 | 文章列表 | "这个能点吗？哇都能点" |
| 传播点 | 文章被转发 | "我发现了一个彩蛋"的分享欲 |
| 风险 | 平淡 | 壳很炫但内容入口埋得深 |

2026 年获奖个人站（Awwwards / Muzli 年度榜单）的共同特征：**motion + storytelling**（动效服务叙事而非炫技）、流畅转场、瀑布流画廊、以及把"作品展示"做成可交互的体验。同时 2026 博客产品共识特性：站内搜索、明暗模式、Newsletter、阅读体验细节（进度、目录、预计阅读时长）、互动信号（阅读量、最近活动）。

### 1.3 核心判断

> PanOS 的桌面外壳已达到该品类"标配线"。下一阶段的竞争力来自两层：
> **① 把桌面从"壳"变成"内容入口"（消费效率）；② 细节惊喜 delight（差异化记忆点）。**
> 所有投入应优先服务"访客更快找到好内容"与"这个站有意思值得逛"两个目标。

## 二、UI 优化空间（按性价比排序）

### 2.1 桌面信息化 —— 最大短板 ⭐⭐⭐⭐⭐

**现状**：打开 PanOS，桌面上除欢迎窗口外一片空白；Widget 只有一个静态 Now 文本卡片。桌面本身没有承载任何内容信息。

**问题**：OS 隐喻里最自然的内容入口（桌面文件、Widget）完全空缺，访客必须先理解 Dock 才能触达内容。

**方案**：
1. **桌面图标**：将 2~3 个精选内容投射为桌面"文件"——最新文章（`.md` 文档图标）、置顶项目（App 图标）、精选照片（图片缩略图标）。双击打开对应窗口；数据来自现有公开 API（`featured` / 最新排序），无需新表。
2. **Widget 体系升级**（桌面右侧栏）：
   - 时钟 / 日期 Widget（纯前端，macOS 风格翻页或模拟表盘）
   - GitHub 贡献热力图（GitHub 公开 API，缓存 1 小时）
   - "正在听" Widget（网易云 / Spotify 最近播放，可后台配置开关）
   - 访客计数 Widget（依赖 2.4 的浏览量统计）
3. Widget 数据走现有 `widgets` 表（type + payload JSONB 已建好），后台 Widgets 管理一并补齐（Phase 5 遗留项）。

**验收**：首屏不打开任何窗口时，访客即可看到 ≥3 条真实内容信号；桌面图标双击直达内容。
**工作量**：前端 3~4 天 + 后台 Widgets 管理 1 天。

### 2.2 欢迎窗口转化路径 ⭐⭐⭐⭐

**现状**：Welcome 窗口三个按钮平铺（开始探索 / 查看最新文章 / 联系我），无视觉重心，纯文本介绍。

**问题**：这是 100% 流量的第一触点，但目前是"装饰"而不是"落地页"。

**方案**：
- 突出一个主 CTA（建议"查看代表作"或"最新文章"），其余降级为次按钮
- 窗口内直接嵌入 1 张置顶内容卡片（封面 + 标题 + 一句话），点击直达
- 增加一行实时感信号："最近更新于 X 天前"（取最新文章 publishedAt）

**验收**：欢迎窗口可直接点进一篇真实内容；主 CTA 点击率可被 2.4 的统计观测。
**工作量**：1 天。

### 2.3 叙事性转场动效 ⭐⭐⭐⭐

**现状**：窗口统一从屏幕中央弹簧弹出；最小化 = 原地淡出消失。

**问题**：macOS 质感的"最后一公里"是**因果连续**——窗口从哪来、回哪去，用户的空间模型不断。

**方案**：
1. **最小化飞向 Dock**（genie 简化版）：窗口 exit 时向对应 Dock 图标位置缩放位移（记录图标 getBoundingClientRect，motion 自定义 exit target）
2. **从触发点生长**：从 Dock / 桌面图标 / Spotlight 打开窗口时，入场动画的 origin 设为点击位置（window-store 记录 openFrom 坐标）
3. Dock 图标在对应 App 打开瞬间加一次弹跳（macOS 启动反馈）

**验收**：最小化后用户能直觉地在 Dock 找回窗口；reduced-motion 下全部降级为淡入淡出。
**工作量**：2~3 天（涉及 window-store 扩展 openFrom/minimizeTo 坐标）。

### 2.4 文章阅读体验 ⭐⭐⭐⭐

**现状**：ArticleReader 有标题 / 元信息 / 正文 / 上下篇，无进度反馈与导航。

**方案**（调研中读者体验的强共识项）：
- 阅读进度条（窗口顶部细线，滚动驱动）
- 目录侧栏（从 markdown heading 提取，桌面端悬浮、移动端折叠——docs/02 原本就有此规划）
- 行宽收紧至 ~68ch，提升长文可读性
- 正文图片点击放大（复用 Gallery 的 Lightbox）
- 文末"相关文章"（同分类最新 3 篇，现有 API 可查）

**验收**：3000 字以上长文在桌面与移动端均可顺畅导航。
**工作量**：2~3 天。

### 2.5 移动端"iOS 感"补完 ⭐⭐⭐

**现状**：主屏网格 + 全屏 App + 按压反馈已具备。

**方案**：
- App 打开转场：从被点击图标的位置缩放展开（与 2.3 共用机制）
- 主屏顶部加状态栏（时间 + 主题切换），替代桌面菜单栏在移动端的缺位
- 主屏支持横向分页（内容 App 一页 / V2 App 一页），底部小圆点指示

**工作量**：2 天。
**备注**：移动端流量通常过半，优先级不应低于桌面端玩具特性。

## 三、功能增量（四象限）

### 3.1 第一象限：高价值 + 低成本（下一迭代就做）

#### F1. Spotlight 全文搜索 ⭐⭐⭐⭐⭐
- **价值**：站内搜索是 2026 博客标配；对 OS 站更是"系统感"核心。现状只能搜 App 名。
- **方案**：后端 `GET /api/search?q=`（聚合 articles / projects / gallery / links 的标题 + 摘要，PostgreSQL `ILIKE` 起步，预留 pg_trgm / 全文索引升级路径）；前端 Spotlight 已有完整键盘交互骨架，结果分组展示（按 App 图标分区），Enter 直达内容窗口。
- **工作量**：后端 1 天 + 前端 1 天。对应 docs/07 Phase 8 的 Spotlight 项。

#### F2. RSS 订阅 ⭐⭐⭐⭐
- **价值**：技术读者硬需求，长期复利的分发渠道。
- **方案**：后端 `GET /feed.xml`（最新 20 篇文章，缓存 5 分钟）；前端菜单栏 / 文章列表暴露 RSS 入口。
- **工作量**：0.5 天。

#### F3. 浏览量统计 ⭐⭐⭐⭐
- **价值**："n 人读过"是信任信号（调研共识）；同时为作者提供内容反馈，为 2.1 访客 Widget 与 2.2 主 CTA 观测提供数据。
- **方案**：新表 `page_views`（path、ip_hash 去重、created_at）；文章 / 项目详情接口附带 viewCount；写入走异步不阻塞响应；隐私上仅存哈希。
- **工作量**：1~1.5 天。

#### F4. 桌面图标 + Widget 升级
- 即 2.1，UI 与功能一体，归入本象限执行。

### 3.2 第二象限：高差异化"人格化 App"（选 1~2 个做记忆点）

#### F5. Terminal App ⭐⭐⭐⭐⭐（推荐首选）
- **价值**：OS 站最出圈的功能；极客人设与"AI Agent Researcher"身份高度匹配；访客会主动截图传播。
- **方案**：新内容 App "Terminal"——黑底等宽字体窗口，支持命令：
  `help` / `ls`（列 App）/ `ls projects`、`cat articles/<slug>`（调现有公开 API）/ `open <app>`（开窗口）/ `whoami`（about 摘要）/ `theme dark|light` / `clear`；未知命令给幽默回复。命令历史 ↑↓、Tab 补全 App 名。
- **工作量**：2~3 天，纯前端（复用现有 API），可渐进增强。

#### F6. Music Widget / App ⭐⭐⭐
- **价值**：人格化展示 + 停留时长抓手。
- **方案**：V1 做"正在听"展示（后台 Settings 手动维护或对接网易云公开接口）；V2 内嵌播放器（注意移动端自动播放限制与版权，建议只放自己有版权的 demo / 白噪音）。
- **工作量**：展示版 1 天；播放器版 3 天+。

#### F7. 彩蛋系统 ⭐⭐⭐
- **价值**：口碑传播来自"我发现了一个彩蛋"。
- **方案**（成本从低到高）：
  - Konami Code（↑↑↓↓←→←→BA）触发壁纸彩蛋 / 全屏动画
  - Terminal 里 `sudo make-me-a-coffee` 之类的幽默命令
  - About 窗口连点 logo 7 次出隐藏成就
  - 深夜访问（本地时间 0-5 点）菜单栏出现"夜猫子"问候
- **工作量**：每个 0.5 天内，可作为每次迭代的"甜点"持续追加。

### 3.3 第三象限：内容运营基建（上线且有持续产出后做）

| 功能 | 说明 | 前置条件 |
| --- | --- | --- |
| F8. Newsletter 订阅 | 2026 博客最强共识；建议接 Buttondown/Listmonk 而非自建发信 | 持续写作节奏成型 |
| F9. Now / Timeline | 数字花园文化的"现在在做什么"；与 Phase 8 Timeline 重合 | 有动态可记录 |
| F10. 公开留言墙 | Contact 升级：留言以便签形式贴在"留言板 App"，比私信更有社区感（需审核机制：后台 Messages 管理先行） | Messages 后台完成 |
| F11. 动态 SEO / OG | 文章/项目详情的 meta 与分享卡片；`react-router` SSR 缺位下可先用 prerender 或边缘函数注入 | 部署上线后 |

### 3.4 第四象限：谨慎投入 / 明确不做

| 项 | 判断 |
| --- | --- |
| 3D / WebGL 大场景（Bruno Simon 路线） | 不做。工程量大、移动端性能差，与 macOS 路线冲突 |
| Ask PanOS（RAG） | 维持 V4。内容量不足时做了也没东西可检索 |
| 实时协作 / 多人在线光标 | 不做。个人站无此场景 |
| 评论系统自建 | 不自建。若要评论接 giscus（GitHub Discussions），但 F10 留言墙优先 |

## 六、风险与原则

1. **壳 > 内容的失衡风险**：本计划一半以上条目服务"内容触达"而非"玩具"，执行时若时间不足，砍玩具保内容入口。
2. **动效性能**：每加一层动效都要过 `prefers-reduced-motion` 与低端移动设备测试；E2E 双视口（Chrome / iPhone 13）已覆盖回归。
3. **依赖克制**：所有新功能优先用现有技术栈（motion / Radix / FastAPI / PostgreSQL）实现，不为单一功能引入新框架。
4. **真实内容先行**：迭代 A 的桌面图标 / Widget 展示的是真实数据——种子数据需在上线前替换为真实文章 / 项目 / 照片，否则一切优化都是给样板间装修。

## 七、设计出彩专项（v1.1 新增）

目标重申：**成为一个很有设计感、出彩的博客**。本章从产品表现 / 功能 / UI·UX 三个视角，
给出超越"达标"的设计升级清单。调研锚点（2026 设计共识）：**排版即品牌资产**、
**微交互是质量信号**、**暗色模式从开关变默认且 OLED 化**、**克制的 calm interface
（反对视觉杂技）**。PanOS 的 macOS 路线天然契合"克制而精致"，应放大这一基因。

### 7.1 产品表现（Presentation & Performance）

#### P1 开机体验（Boot Sequence）⭐⭐⭐
- **现状**：刷新即白屏 → 桌面直出，缺一个"开机"的仪式感。
- **方案**：每会话首次进入播放 0.8~1.2s Apple 风格开机序列（居中 logo + 细进度条
  → 淡出进桌面，与欢迎窗弹出衔接成一镜）；点击可跳过；`prefers-reduced-motion`
  与会话内刷新直接跳过。
- **验收**：开机 → 桌面 → 欢迎窗三段动效连续无跳变；跳过路径 < 100ms 进桌面。

#### P2 品牌锚点 ⭐⭐⭐⭐⭐（设计感的根基）
- **现状**：没有 logo，菜单栏用 "◆" 占位，favicon 是 Vite 默认图标，OG 卡片是壁纸原图。
  没有识别度，一切视觉打磨都缺少署名。
- **方案**：设计 PanOS logomark（建议方向：圆角方形 App 图标语言里的 "P" 字形，
  渐变取自精灵崖海蓝）；落地到 favicon（SVG + PNG 多尺寸）、菜单栏、开机序列、
  OG 分享卡片模板（logo + 标题 + 渐变底）、About 窗口。
- **验收**：浏览器标签页 / 分享卡片 / 站内三处品牌一致。

#### P3 性能即设计 ⭐⭐⭐⭐
加载的每一毫秒都是第一印象的一部分：
- 壁纸 1.1MB JPG → **AVIF/WebP 双格式 + `<picture>` 降级**，目标 ≤ 300KB；
  加载期间用 CSS 渐变近似色打底，图就位后淡入（blur-up）
- 主 bundle 超 500KB 警告处理：MDXEditor / highlight.js 已 lazy，
  再拆 react-markdown 链路与 admin 路由 chunk
- 字体策略：标题字体子集化（仅常用字 + 站点文案），`font-display: swap`，
  正文走系统栈避免 FOUT
- **验收**：本地 Lighthouse Performance ≥ 90，LCP ≤ 1.8s（模拟 Fast 3G 桌面）。

#### P4 状态设计化 ⭐⭐⭐
- 加载态：文本"加载中…"全部替换为**骨架屏 shimmer**（卡片网格出灰块呼吸）
- 空态：EmptyState 配上用 App 强调色渐变绘制的简约插画（SVG 内联），
  替代纯图标，让"还没有内容"也有设计表达
- **验收**：站内不再出现纯文本加载/空提示。

### 7.2 功能视角（Design-driven Features）

#### N1 壁纸系统 ⭐⭐⭐⭐
Preferences 增加「桌面与壁纸」分区：内置 2~3 张精选壁纸（精灵崖 + 1 张深色系 +
1 张纯渐变）缩略图选择，localStorage 记忆；可选项「日落后自动切换深色壁纸」
（按本地时间 18:00/6:00）。macOS 设置即视感，成本约 1 天。

#### N2 控制中心 ⭐⭐⭐（Phase 9 提前）
菜单栏右侧新增控制中心入口，弹出 macOS 风格聚合卡片：主题三态、壁纸快切、
声音开关（配合 N3）、动效开关（软性 reduce-motion）。把散落的偏好聚合成
一个有辨识度的交互面板。约 1~1.5 天。

#### N3 声音设计 ⭐⭐（默认关闭）
开机声、窗口开/关、Dock 弹跳的细微音效（Web Audio 合成或 <30KB 采样）。
**默认静音**，控制中心/Preferences 开启后 localStorage 记忆。
OS 沉浸感的放大器，但绝不能违背"calm interface"——故默认关。

#### N4 阅读偏好 ⭐⭐⭐（并入迭代 B）
文章阅读器字号三档（S/M/L）+ 阅读位置记忆（localStorage，重开窗口恢复滚动位置）。

#### N5 中英双语（i18n）（第三象限，暂缓）
受众扩展价值高但工作量大（全站文案 + 内容双语）。建议等真实内容与流量验证后，
先做 About/Welcome 双语，再评估全站。

### 7.3 UI·UX 细节清单（Quality Checklist）

#### U1 排版个性 ⭐⭐⭐⭐⭐（性价比最高的设计升级）
- **现状**：全站单一 Inter + 系统中文栈，工整但无记忆点。
- **方案**：引入一款**衬线中文字体（如 Noto Serif SC / 思源宋体）只用于三处**——
  欢迎窗主标语、文章标题与阅读器 h1/h2、About 个人宣言。正文保持无衬线。
  「无衬线系统 UI + 衬线内容标题」的对比，正是"操作系统里住着一个写作者"的
  视觉叙事；同时建立字阶模数（1.25）与中文行高节奏（正文 1.75）。
- **验收**：阅读器与欢迎窗有明确的排版层级与个性；标题字体子集 ≤ 150KB。

#### U2 色彩故事 ⭐⭐⭐⭐
- **现状**：色板是默认感的 Tailwind 蓝紫，与精灵崖壁纸没有呼应。
- **方案**：从壁纸取色重定义品牌主色（海蓝 #0E7490 系 → 青绿渐变），
  贯穿 primary token、AppIcon 渐变基调、selection 色、链接色；
  暗色模式重做层次——背景接近纯黑（OLED 友好），surface 用半透白分 2~3 个
  elevation 级，而非简单变量反转。
- **验收**：浅/暗两套色板都能讲出"海"的色彩故事；对比度全部过 WCAG AA。

#### U3 微交互一致性 ⭐⭐⭐⭐
- 全站交互节奏规范化：hover 120ms / 按下 90ms / 出场 160~200ms，统一缓动 token
- **窗口内容滚动时 titlebar 出现分层投影**（macOS 真实行为，scroll 联动）
- 表单校验失败时窗口轻微 shake（±6px，3 次，reduced-motion 降级为边框闪烁）
- Dock 图标在 App 打开瞬间弹跳一次（与 2.3 同场施工）
- **验收**：动效 token 落进 tokens.css，新组件默认遵循。

#### U4 图片体验 ⭐⭐⭐
- **启用 blurhash**：`media_assets.blurhash` 字段建表时就有但从未写入/使用——
  上传时计算（后端 Pillow + blurhash 库），前端 Gallery/封面 blur-up 渐进显示
- Gallery 从等高网格升级为真 masonry（CSS columns 或 grid dense）
- Lightbox 补双击/滚轮缩放
- **验收**：弱网下图片区域无白块闪烁，始终有模糊占位。

#### U5 文字与代码细节 ⭐⭐⭐
- `::selection` 用品牌色；`focus-visible` 环全站统一（已有基础，补遗漏组件）
- 文章代码块升级为 mac 终端样式：圆角深底 + 红黄绿装饰点 + 语言标签 + 复制按钮
- 中文排版细节：引号悬挂、数字与中英文间距（`text-autospace` 渐进增强）
- **验收**：长文阅读页截图可直接当作品集展示。

#### U6 明确不做（守住 calm interface 底线）
| 项 | 理由 |
| --- | --- |
| 自定义光标 | 损害可用性，与 macOS 拟真冲突 |
| 大面积 kinetic typography | 与克制路线冲突；至多欢迎窗标语一处可考虑入场动画 |
| 声音默认开启 | 侵扰性；永远 opt-in |
| 滚动劫持 / 视差长页 | PanOS 是窗口范式，不是滚动叙事范式 |

## 八、桌面舞台与 macOS 拟真专项（v1.2 新增）

针对反馈：**「中间存在大片留白，不够美观；整体风格和 mac 桌面不够像」**。
本章先诊断成因，再给出按优先级排序的方案。指导原则：真 macOS 桌面之所以
不显得空，是因为桌面本身是**有内容的工作台**（文件、便签、Widget、常开的窗口），
而不是一张壁纸 + 一条 Dock。

### 8.1 留白诊断：三个结构性成因

| 成因 | 现状 | 后果 |
| --- | --- | --- |
| 桌面元素太少且贴边 | 左上仅 3 个图标（单列窄条），右侧 1 列窄 Widget（260px） | 1440px 视口下中央约 60% 面积是纯壁纸 |
| 无窗口时没有舞台内容 | 关闭欢迎窗后中央完全空白 | 访客把窗口全关后页面"死"了 |
| 窗口默认尺寸偏小 | 固定 880px，宽屏（≥1920px）下占比 < 50% | 即使开着窗口也两侧大片留白 |

### 8.2 桌面填充方案（按性价比排序）

#### D1 桌面图标网格扩容 ⭐⭐⭐⭐⭐（最 mac 的填充方式）
- **现状**：3 个图标单列贴左上。真 macOS 桌面的图标默认**从右上角往下排**，
  且常常排满一两列。
- **方案**：桌面图标扩为**两列内容投影**（约 8~10 个）：
  最新 3~4 篇文章（`.md` 文档图标）、2 个置顶项目（App 图标）、
  2~3 张照片缩略图、1 个「简历.pdf」（打开 About）。图标移到**右侧区域**
  （mac 默认位），Widget 列移到左侧（Sonoma 桌面 Widget 的常见位置）。
- 上限 10 个，超出的内容仍归 App 管——桌面是精选投影，不是文件堆。
- **验收**：1440px 视口下，壁纸裸露面积 < 40%；图标双击直达内容（机制已有）。

#### D2 Stickies 便签 ⭐⭐⭐⭐（经典 mac 元素 + 人格化）
- 桌面上贴 1~2 张**黄色便签**（手写感排版）：一张写欢迎语/当前状态，
  一张写"最近在忙什么"（内容走 widgets 表，后台可改）。
- 轻微随机旋转（-2°~2°）+ 纸张阴影；可拖拽（复用窗口拖拽逻辑的简化版）。
- 这是 OS 拟真和"有人住在这里"感的高性价比结合点。

#### D3 Widget 棋盘化（bento grid） ⭐⭐⭐⭐
- **现状**：右侧单列 4 个小卡片，信息密度低。
- **方案**：参考 Apple 官网 bento 布局与 macOS Sonoma 桌面 Widget：
  2 列不等高棋盘（2x2 时钟、2x1 GitHub 热力、1x1 访客、2x2 **日历月视图
  小部件**（直接把月历缩略放上桌面，点击放大——日历放大交互已有）、
  1x1 正在听）。
- **验收**：Widget 区从"边栏"变成"桌面的一部分"，与 D1 图标共同消化留白。

#### D4 窗口尺寸自适应 ⭐⭐⭐⭐（一行改动级别的高收益）
- 窗口宽度从固定 880px 改为 `min(1080px, 74vw)`、高度 `min(720px, 78%)`，
  宽屏下窗口占比明显提升；多窗口层叠步距同步调大。
- **验收**：1920px 视口下单窗口宽度 ≥ 1080px。

#### D5 默认开窗策略 ⭐⭐⭐
- 欢迎窗关闭后中央不再"死"：关闭最后一个窗口时，桌面中央淡入一行
  幽灵提示（"双击桌面图标，或按 ⌘K 搜索"，8 秒后消失）；
- 可选（默认关）：首访时在 Welcome 后方平铺一扇 Articles 窗口，
  营造"正在使用中的桌面"。

### 8.3 macOS 拟真清单（像不像的关键差距）

#### M1 完整菜单栏 ⭐⭐⭐⭐⭐（当前最大的拟真差距）
- **现状**：菜单栏只有 PanOS 一个菜单 + 右侧三个图标，真 mac 菜单栏有
  App 菜单组（File/Edit/View/Window/Help）和右侧状态区。
- **方案**：
  - 左侧补 **文件 / 显示 / 窗口 / 帮助** 四个真菜单（不是装饰）：
    显示 → 切换主题/壁纸；窗口 → 列出所有打开窗口可聚焦/全部最小化；
    帮助 → 打开 About / 快捷键列表；文件 → 新建留言（开 Contact）、订阅 RSS
  - 右侧状态区补图标：Wi-Fi（hover 显示"已连接到 PanOS 网络"彩蛋）、
    电池（显示访客"探索电量"，随浏览时长增长——彩蛋）、控制中心入口（N2）
- **验收**：菜单栏信息结构与真 macOS 同构；每个菜单项都有真实行为。

#### M2 桌面右键菜单 ⭐⭐⭐⭐
- 桌面空白处右键弹出 mac 风格上下文菜单：更换壁纸（N1）、整理图标、
  切换深浅色、关于 PanOS。拟真感跃升的关键交互——访客一定会试右键。

#### M3 桌面框选（rubber-band selection） ⭐⭐
- 按住拖拽出半透明蓝色选框，可框选桌面图标（高亮但无后续动作）。
  纯拟真装饰，成本约半天，"哇这都做了"的细节。

#### M4 Dock 收尾 ⭐⭐⭐
- 内容 App 与系统区之间加**分隔线**；末位加**废纸篓**（彩蛋：打开显示
  "回收站是空的——被删掉的想法都已经重生为文章"）。

### 8.4 顶级网站设计元素移植

| 元素 | 来源 | 在 PanOS 的落点 |
| --- | --- | --- |
| 壁纸视差景深 | 获奖作品的 layering 共识 | 鼠标移动时壁纸反向平移 1~2%、桌面图标 0.5%，制造三层景深；reduced-motion 关闭 |
| 噪点纹理（grain） | 高端站常用的"去数码感" | 壁纸上叠 2% 透明噪点层，毛玻璃质感更接近实物 |
| bento grid | Apple 官网 | D3 Widget 棋盘 |
| 大字版式 hero | 2026 排版趋势 | 欢迎窗主标语用衬线大字号（与 U1 同场施工） |

### 8.5 执行建议

```text
新迭代 F「桌面舞台」（约 1 周，优先级排在 RSS/阅读体验之前——
视觉第一印象 > 长尾功能）：
  D4 窗口自适应（先做，半天见效）
  D1 图标网格扩容 + 右排 / Widget 左移
  D3 Widget 棋盘化（含日历月视图小部件）
  M1 完整菜单栏 + 状态区
  D2 Stickies 便签
  M2 桌面右键菜单
  视差 + 噪点（与 D1 同场）
  M3/M4/D5 视余量
  ── 验收：1440px 无窗口状态下截图可直接当作品集；
     「这是不是真的 macOS」的第一眼迟疑时间显著变长
```
