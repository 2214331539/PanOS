# 技术架构文档

版本：v0.2  
日期：2026-06-07

## 架构目标

PanOS 需要同时满足三个目标：

1. 公开站点有强交互桌面体验。
2. 内容可以通过后台长期维护。
3. 前后端职责清晰，前端专注桌面式体验，后端专注内容 API、鉴权、数据、媒体和未来 AI 能力。

## 唯一技术栈

以下技术栈为本项目唯一选型。不得在未更新文档和获得明确同意前替换。

| 层级 | 唯一选型 | 说明 |
| --- | --- | --- |
| 仓库结构 | Monorepo | `apps/web` 放 React 前端，`apps/api` 放 Python 后端 |
| 前端语言 | TypeScript | 前端、组件、类型定义统一使用 TypeScript |
| 前端框架 | React 19 + Vite | 公开桌面、后台管理和所有交互界面 |
| 前端路由 | React Router | 桌面内 App 状态和直达路由统一管理 |
| 前端包管理器 | pnpm | `apps/web` 唯一包管理器 |
| 样式 | Tailwind CSS + CSS Variables | Tailwind 负责布局和原子样式，CSS Variables 负责主题 token |
| 组件基础 | Radix UI primitives | 只用于 Dialog、Dropdown、Tooltip、Tabs、Popover 等无障碍基础组件 |
| 图标 | lucide-react | Dock、按钮、菜单统一使用 |
| 动效 | Motion | 唯一动效库 |
| 前端状态 | Zustand | 管理窗口、Dock、Spotlight、主题等客户端状态 |
| 前端数据请求 | TanStack Query | 公开内容、后台列表、缓存和请求状态 |
| 表单 | React Hook Form + Zod | 前端表单状态和客户端校验 |
| 富文本内容 | 受限 MDX / Markdown + 白名单渲染 | 正文存数据库，前端渲染，组件必须白名单 |
| 后端语言 | Python 3.12 | API、鉴权、数据访问、媒体处理和未来 AI 能力 |
| 后端框架 | FastAPI | 公开 API、后台 API、OpenAPI 文档 |
| 后端包管理器 | uv | `apps/api` 唯一 Python 包管理器 |
| 后端校验 | Pydantic v2 | 请求、响应、配置和领域 schema |
| ORM | SQLAlchemy 2.0 async | 数据模型和类型化查询 |
| 数据库迁移 | Alembic | 数据库 migration |
| PostgreSQL 驱动 | asyncpg | FastAPI 异步访问 Supabase PostgreSQL |
| 数据库 | Supabase PostgreSQL 16 | 内容、设置、留言、后台数据 |
| 身份认证 | Supabase Auth + FastAPI JWT 校验 | Supabase 负责登录，FastAPI 校验 token 和管理员权限 |
| 对象存储 | Supabase Storage | 图片、视频、简历、封面等文件 |
| 缓存 | HTTP Cache-Control + ETag + CDN Cache + TanStack Query Cache | V1 不引入 Redis |
| 搜索 | PostgreSQL Full Text Search + `pg_trgm` | V2 Spotlight 使用 |
| 前端测试 | Vitest + React Testing Library + Playwright | 单元、组件、端到端和视觉检查 |
| 后端测试 | pytest + pytest-asyncio + httpx | API、service、schema、权限测试 |
| 代码质量 | ESLint + Prettier + TypeScript strict + Ruff + mypy | 前后端提交前必须通过 |
| 前端部署 | Vercel Static Hosting | 承载 React 构建产物 |
| 后端部署 | Railway Docker Web Service | 承载 FastAPI |
| 数据和存储部署 | Supabase | 承载 PostgreSQL、Auth、Storage |

## 禁止的替代选型

- 不使用 Vue、Nuxt、Svelte、Astro 替代 React。
- 不使用 Next.js Route Handlers、Express、Koa、NestJS 承担业务后端。
- 不使用 Django、Flask 替代 FastAPI。
- 不使用 Prisma、Tortoise ORM、Django ORM 替代 SQLAlchemy。
- 不使用 MongoDB、MySQL、SQLite 替代 PostgreSQL。
- 不使用 Firebase、Cloudinary、S3、R2 替代 Supabase Storage，除非更新架构文档。
- 不使用 Redux、MobX、Jotai 替代 Zustand。
- 不使用 Motion 以外的第二套动效库。
- 不使用 Algolia、Meilisearch、ElasticSearch 替代 PostgreSQL 搜索，除非进入单独搜索升级阶段。

## 总体架构

```text
Browser
  |
  | React app, React Router, TanStack Query, Zustand
  v
apps/web
  |
  | HTTPS JSON API, Bearer access token for admin requests
  v
apps/api FastAPI
  |
  | SQLAlchemy async queries, Supabase JWT verification, Storage operations
  v
Supabase
  |-- PostgreSQL
  |-- Auth
  |-- Storage
```

## 数据流

### 公开桌面启动

1. 访问 `/`，Vercel 返回 React 构建产物。
2. React 初始化主题、窗口状态、Dock、Spotlight 快捷键。
3. 前端调用 `GET /api/desktop/bootstrap` 获取公开设置、Widget、最新内容。
4. Dock App 配置来自前端代码常量。
5. 内容 App 打开后通过 TanStack Query 按需调用 FastAPI 公开接口。

### 内容详情直达

1. 访问 `/articles/[slug]` 或 `/projects/[slug]`。
2. Vercel fallback 到 React 应用。
3. React Router 解析 slug。
4. 前端调用 FastAPI 详情接口。
5. 如果内容不存在或不可见，显示 PanOS 404 状态。

说明：V1 使用 React SPA 直达路由。SEO 通过静态默认 meta、sitemap、Open Graph 基础信息和搜索引擎 JS 渲染支持；如果后续文章 SEO 成为主要目标，再单独评估 SSR 或预渲染方案，并先更新本文档。

### 后台编辑发布

1. 管理员在 `/admin/login` 使用 Supabase Auth 登录。
2. 前端保存 Supabase access token。
3. 后台请求以 `Authorization: Bearer <token>` 调用 FastAPI。
4. FastAPI 校验 Supabase JWT，并查询 `admin_users` 确认管理员身份。
5. FastAPI 使用 SQLAlchemy 写入 PostgreSQL。
6. 内容更新后返回成功，由前端主动刷新相关 TanStack Query cache；公开 GET 接口通过 ETag 和 CDN 缓存控制降低重复请求。

## 缓存策略

| 数据 | 策略 |
| --- | --- |
| 首页 bootstrap | FastAPI 返回 `Cache-Control: public, max-age=60, stale-while-revalidate=300` |
| 文章列表 | HTTP cache + ETag + TanStack Query cache |
| 文章详情 | HTTP cache + ETag，内容更新后 ETag 变化 |
| 项目列表 | HTTP cache + ETag + TanStack Query cache |
| Gallery | HTTP cache + ETag + TanStack Query cache |
| Links | HTTP cache + ETag + TanStack Query cache |
| Widgets | HTTP cache + ETag + TanStack Query cache |
| 后台接口 | `Cache-Control: no-store` |
| 搜索 | 不做持久缓存，依赖 PostgreSQL 索引 |

V1 不引入 Redis。只有当搜索、访问量、后台任务或 AI 索引明确超出 HTTP/CDN/客户端缓存能力时，才能新增缓存服务，并必须先更新本文档。

## 对象存储策略

Supabase Storage bucket：

| Bucket | 访问权限 | 用途 |
| --- | --- | --- |
| `panos-public-assets` | public read | 公开图片、封面、Gallery、壁纸 |
| `panos-private-assets` | private | 未发布素材、原始文件、草稿文件 |
| `panos-downloads` | public read 或 signed URL | 简历 PDF、可下载附件 |

所有媒体都必须在 `media_assets` 表登记元数据。前端不得直接依赖裸文件路径作为唯一数据源。

## 权限策略

- 公开 API 只返回 `status='published'` 且 `visibility='public'` 的内容。
- 后台 API 必须同时满足 Supabase JWT 有效和 `admin_users.is_active=true`。
- 只有 `owner` 角色可以修改站点设置和删除媒体。
- 公开 Contact 表单必须做 Pydantic 校验、频率限制和基本反垃圾字段。
- 前端不得直接写数据库或直接调用 Storage 写入，所有写操作必须经过 FastAPI。

## 安全约束

- `SUPABASE_SERVICE_ROLE_KEY` 不得出现在前端构建产物。
- FastAPI 必须开启严格 CORS，只允许正式站点、预览站点和本地开发地址。
- 后台 API 必须使用 Supabase access token，并在后端二次查询 `admin_users`。
- 受限 MDX / Markdown 渲染只允许白名单组件，不允许任意脚本。
- 后台表单必须同时有前端 Zod 校验和后端 Pydantic 校验。
- 删除操作默认软删除或归档，媒体硬删除仅 owner 可执行。
- 外链必须带 `rel="noopener noreferrer"`。
- 上传文件必须限制 MIME、大小和扩展名。

## 部署

| 环境 | 前端 | 后端 | 数据和存储 |
| --- | --- | --- | --- |
| Local | Vite dev server | Uvicorn + FastAPI | Supabase local 或远程 dev 项目 |
| Preview | Vercel Preview | Railway preview service | Supabase dev |
| Production | Vercel Production | Railway production service | Supabase prod |

后端必须提供 Dockerfile，Railway 通过 Docker 部署 FastAPI。前端通过 Vercel 构建 `apps/web`。

部署前必须通过：

1. `pnpm --dir apps/web lint`
2. `pnpm --dir apps/web typecheck`
3. `pnpm --dir apps/web test`
4. `pnpm --dir apps/web test:e2e`，至少覆盖首页、文章详情、后台登录保护
5. `uv run --project apps/api ruff check .`
6. `uv run --project apps/api mypy app`
7. `uv run --project apps/api pytest`
8. Alembic migration 状态检查
